# Agent Execution Boundaries

## Rules

1. Touch one file per turn.
Reason: Single edits keep diffs small and prevent cascading syntax breaks across the project.

2. Do not install or add npm packages without user consent.
Reason: Unapproved dependencies increase bundle size and introduce security liabilities.

3. Never run Prisma migrations, pushes, or schema mutation commands in the terminal.
Reason: Schema changes must be reviewed manually to avoid dropping tenant data or breaking relations.

4. Validate zero token violations before finishing any task.
Reason: The product mandates absolute token compliance; arbitrary colors break the design system.

5. Stop and ask questions whenever requirements are absent.
Reason: Guessing creates scope drift and forces costly rewrites later.

6. Report every assumption at the end of each response.
Reason: Explicit assumptions allow immediate correction before errors compound.
