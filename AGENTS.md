# AGENTS.md

## Description
BeltTrack is a private multi-tenant martial arts school management platform for dojo owners, coaches, students, and guardians.
The platform acts as a closed single source of truth for curriculum progress, belt ranking eligibility, attendance, and internal tuition records.
It operates with strict tenant isolation, zero monetization, and a token-compliant design system.

## Who uses it
- Dojo Owner or Head Coach: Previews school registration, join code generation, and role switching without building full admin management screens.
- Coach or Instructor: Takes attendance and verifies student techniques in real time during live classes without permissions to backdate records.
- Student (Adult 18+): Enters a join code to view a pending confirmation notice and previews personal rank progress, attendance, and internal receipts.
- Guardian or Parent: Views dependent attendance, progress, and receipts strictly through linked read-only preview states.

## One thing that the agent must do well
Enforce strict multi-tenant isolation and verify zero hardcoded styling values by ensuring npm run audit passes with zero errors.

## Defined Scope for the MVP
- Full Next.js 14+ App Router project structure with strict TypeScript.
- Standalone static interactive preview files: index.html, index.css, app.js, and server.js.
- Token pipeline compiling tokens-complete.json through build-tokens.js into variables.css and typography.css.
- Automated token compliance test runner audit.js running via npm run audit.
- Custom tailwind.config.ts mapping utility classes directly to CSS variables.
- PostgreSQL schema using Prisma ORM with school_id foreign key relations, database-level Row-Level Security, and Prisma query extensions.
- Context state files for persona auth and school_id tenant scoping.
- Responsive top navigation with tenant indicator and interactive role switcher.
- Hero section outlining core pillars and architectural overview.
- Role-based onboarding entry modals for school registration and join code entry.
- Interactive rank preview displaying White-to-Blue belt progress (42/50 classes, 142/120 days, 8/10 techniques) and a check-in simulation button.
- Preview displays for roll-call schedules, inactive student risk indicators flagged after 10 or more days of absence, and immutable ledger entries.
- Public directory view listing accredited schools using only name, slug, city, and discipline.

## Not in scope items for the MVP
- External payment gateway processing.
- Outbound push notifications, SMS dispatch, or third-party transactional email workers.
- Native camera barcode or QR scanner drivers.
- Native iOS or Android mobile builds.
- Production background worker cron jobs.

## Stack
- Framework: Next.js 14+ App Router
- Language: TypeScript with strict mode
- Database: PostgreSQL
- ORM: Prisma
- Styling: Tailwind CSS mapped to CSS Custom Properties generated from tokens-complete.json via build-tokens.js
- Validation: Zod
- Runtime: Node.js

## Folder map
- src/app: Root layout and home page
- src/components/home: Hero section, preview dashboard, and role entry cards
- src/components/layout: Top navigation component
- src/context: Auth context and tenant context providers
- src/lib/validation: Zod schemas for forms and entities
- src/styles: Global Tailwind styles and tokens import layer
- src/types: TypeScript domain models
- Root directory: Standalone preview files, token compiler, audit script, and configuration files

## How to work in this codebase
- Apply only one change at a time.
- Ask for user approval before installing or adding new packages.
- Never run database migrations, pushes, or modifications through any tool or script unless explicitly ordered.
- Every private record must bind strictly to the school_id column.
- Ledger entries are immutable and append-only; corrections must be offsetting reversal entries.
- List all assumptions at the end of every response.
- Stop and ask when the PRD is silent about any requirement, workflow, or behavior.
- Run npm run audit to confirm zero hardcoded styling values exist before completing work.

## Definitions
- Tier: No feature tiers exist; the platform has zero tiers, zero feature paywalls, and zero tiered subscriptions.
- Record: A private entity belonging to a single school tenant, inaccessible to unapproved users and cross-tenant queries.
- Receipt Slug: An immutable identifier following the exact format REC-[YEAR]-[DISCIPLINE]-[INCREMENT].
- Join Code: An alphanumeric code generated by a school to allow users to register under pending approval status.
- PENDING_APPROVAL: Account state assigned after entering a join code that blocks all reads to rosters and techniques until admin sign-off.
- Chunk: The PRD does not define this term.
